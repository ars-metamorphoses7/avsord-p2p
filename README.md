JUMP é basicamente o Discord que caiu de cabeça no Windows 98, tomou café demais e decidiu se hospedar na sua própria rede: você cria uma sala e troca mensagens, arquivos, áudio e câmera diretamente entre os computadores via WebRTC. O vídeo da tela continua P2P com até dois espectadores; a partir de três, o servidor encaminha uma única transmissão por um SFU, mantendo o P2P pronto como fallback. O histórico fica local no IndexedDB (até ~500 MB/50 mil mensagens por conversa), arquivos vão em blocos P2P (até 200 MB) e ninguém precisa criar conta.

Para desenvolver, rode `npm install` e `npm run dev`; para a experiência completa, use a release desktop para Windows ou Linux. Conecte todos à mesma rede/Radmin VPN, abra o JUMP no host com `npm run desktop`, permita TCP `8787` e UDP/TCP `40000–49999` no firewall, e envie um convite `jump://join?signal=http%3A%2F%2FIP-RADMIN%3A8787&room=ID-DA-SALA`. Em hosts com várias interfaces, defina `JUMP_SFU_ANNOUNCED_ADDRESS` com o IPv4 alcançável pelos convidados. Releases e instaladores ficam em [ars-metamorphoses7/avsord-p2p](https://github.com/ars-metamorphoses7/avsord-p2p).

Em **Configurações → Atalhos da chamada**, clique na combinação para gravar outro bind (Esc cancela). Os padrões são **Ctrl+Shift+M** (mutar/desmutar) e **Ctrl+Shift+D** (ensurdecer); funcionam só durante uma chamada e não entram em chamadas automaticamente. A preferência fica salva neste computador. No desktop o atalho é global, inclusive com o JUMP em segundo plano; no navegador ele funciona com a página em foco, fora de campos de texto. Se outro aplicativo reservar a combinação, as configurações avisam e permitem escolher outra.

O **JUMP Jukebox** aparece no painel da chamada: cole um link de vídeo do YouTube e clique em **Adicionar**. A fila (até 30 vídeos), pausa, retomada e próxima faixa são compartilhadas pela sala. O volume é local e o botão de desativar áudio também silencia a música. É um player oficial do YouTube sincronizado entre clientes, sem conta, chave de API, download ou retransmissão do áudio pelo microfone. Cada participante precisa de acesso ao YouTube; vídeos privados, removidos, com restrição de incorporação ou bloqueio de autoplay podem exigir interação ou não tocar. A sincronização é aproximada e anúncios/buffering podem gerar diferenças. A reprodução local para ao sair ou fechar o painel da chamada; ao reabrir, acompanha a posição compartilhada. A fila é temporária e é apagada quando a sala fica vazia ou o servidor reinicia. Todos precisam usar uma versão compatível, inclusive o host.

**Servidores e posse.** Cada JUMP desktop roda um servidor; o botão de globo no topo da barra lateral abre **Servidores**. Cada servidor tem um ID fixo (salvo em `server.json` na pasta de dados), então quando o IP do host muda (Radmin novo, PC formatado) basta usar **Alterar endereço** — todas as salas salvas daquele servidor passam para o novo IP. Se o servidor salvo não responde, o aviso no rodapé oferece **Alterar endereço…** e **Usar este PC**. Na mesma janela o host escolhe qual IP vai nos convites. O PC que hospeda o servidor administra todas as salas; fora isso, só quem criou a sala pode renomeá-la, excluí-la ou passar a posse (em **Informações da sala**). Salas antigas, sem dono, ficam com o host. Se o criador formatar o PC, o host continua podendo gerenciar e repassar a sala.

Validação dos binds e da fila: `npm run test:persistence`. Validação da interface com dois participantes: `npm run build` seguido de `npx electron tests/music-bind.e2e.cjs` e `npx electron tests/servers-ui.e2e.cjs`.

No Linux, o áudio pode ser capturado por janela/aplicativo a partir do stream ativo do PulseAudio/PipeWire. Para compartilhar o áudio geral, selecione uma tela: o JUMP é excluído automaticamente da mistura para evitar que os participantes ouçam o próprio retorno da chamada. O sistema precisa disponibilizar `pactl` ou `pw-dump` e `parec` ou `pw-record`; para áudio por janela, reproduza algum áudio no aplicativo antes de selecioná-lo.
